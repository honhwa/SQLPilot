## نصب

۱. نصاب را از Releases رسمی دریافت کن.

۲. کوئری‌ها را ذخیره کن؛ برای آماده‌سازی نصب می‌توانی SSMS را باز نگه داری.

۳. نصاب را اجرا کن، نسخه‌های مورد نظر را انتخاب کن و نصب را انجام بده. نصب میزبان به دسترسی Administrator نیاز دارد.

۴. اگر SSMS باز است، آن را بعد از آماده‌سازی ببند و منتظر پایان نصب بمان. دکمهٔ Open SSMS در ردیف همان نسخه بعد از نصب موفق فعال می‌شود؛ در تب کوئری متصل، دکمهٔ **SqlPilot** را در نوار ابزار پیدا کن.

## امکانات

نسخه‌های جدید گیت‌هاب در پس‌زمینه بررسی می‌شوند. از منوی SQLPilot گزینهٔ **Check for updates** یا **Update to…** را بزن تا نصاب دانلود و باز شود؛ روی دکمهٔ اصلی هم نشان Update نمایش داده می‌شود.

- پیشنهاد جدول، ستون، اسکیما، تابع و پارامترهای Stored Procedure با فیلتر تلفیقی و alias.
- با تأیید جدول بعد از `INSERT INTO`، ستون‌های قابل درج و بدنهٔ `VALUES` با نوع ستون در کامنت ساخته می‌شود. default ستون اولویت دارد؛ ستون nullable مقدار `NULL` و ستون اجباری مقدار اولیهٔ متناسب با نوع می‌گیرد. با Tab بین مقدارها حرکت کن؛ ادامهٔ دستور موجود حفظ می‌شود.
- پیشنهاد JOIN و شرط ON براساس foreign keyهای قابل مشاهده، شامل روابط چندستونی.
- تبدیل `*` در بخش SELECT به ستون‌های زیر هم با Tab، همراه راهنمای کوچک در ویرایشگر.
- شورتکات‌های قابل تغییر، اسنیپت‌هایی مثل `ssf`، خطا و هشدار با توضیح و اصلاحات امن.
- مرتب‌سازی با حفظ کامنت‌ها، تبدیل عملگرهای اشتباه، کتابخانهٔ SQL با دسته‌بندی و جستجو، هیستوری و بازیابی تب‌ها.
- در کتابخانه، آخرین کوئری درج‌شده بالای لیست و هنگام باز شدن انتخاب است؛ با ↑ و ↓ انتخاب را عوض کن و با Ctrl+Enter آن را در کوئری درج کن.

Ctrl+Space پیشنهادها را باز می‌کند؛ Tab/Enter تأیید می‌کند و Esc می‌بندد. Alt+Enter یا Ctrl+. توضیح خطا و اصلاحات را نشان می‌دهد. Ctrl+Shift+F برای مرتب‌سازی، F12 برای رفرنس و Ctrl+F12 برای Object Explorer است. همهٔ کلیدها در Keyboard shortcuts قابل تغییرند.

رابط ابزار و نصاب انگلیسی است. پیشنهادها و بررسی‌ها محلی‌اند؛ اصلاحات و اسکریپت رفرنس فقط متن ویرایشگر را تغییر می‌دهند و SQL اجرا نمی‌کنند. اطلاعات و فایل‌های کاربر زیر `%LOCALAPPDATA%\SqlPilot` نگه‌داری می‌شوند؛ متن و کانکشن سشن با DPAPI حساب ویندوز محافظت می‌شوند. فایل‌های Library و History ممکن است SQL حساس داشته باشند و باید دسترسی به آن‌ها را محافظت کرد.

## سازگاری و ساخت

نصاب میزبان‌های SSMS نصب‌شده را شناسایی می‌کند و آداپتر را با API همان میزبان می‌سازد. دسترسی به متادیتا، روش اتصال و API میزبان روی عملکرد اثر می‌گذارد. جزئیات در [راهنمای ساخت](docs/BUILDING.md) و [وضعیت تست](docs/VALIDATION.md) آمده است.

برای ساخت، ویندوز، SDK تعیین‌شده در global.json، PowerShell و میزبان SSMS نصب‌شده لازم است:

```powershell
pwsh -File scripts/Test.ps1
pwsh -File scripts/Build.ps1
pwsh -File scripts/Build-Setup.ps1
```
